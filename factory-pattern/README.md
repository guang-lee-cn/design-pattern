# factory-pattern · C++ 工厂模式

> 创建型模式 · **按知识骨架推进，不按篇数规划**

## 从哪读起

| 入口 | 内容 |
|---|---|
| [`docs/`](docs/) | 正文（markdown + 内嵌 Mermaid），一篇文章一个文件 |
| [`code/`](code/) | 配套 C++ 工程，随节增量增长，可独立编译 |
| [`notes/`](notes/) | 写作过程中的问题记录与复盘 |

知识骨架、节的依赖顺序、体例要求见仓库根 [`TEMPLATE.md`](../TEMPLATE.md)。
素材来源与写作排期在仓库外，不随本仓库发布。

**协作方式**：`docs/` 与 `notes/` 由助手在聊透后落盘；`code/` 全部由使用者手敲、亲手构建验证（见根 [`AGENTS.md`](../AGENTS.md) §0）。

## 按骨架推进

一个**节**是知识单元，一篇**文**是阅读单元：一节可以写成一篇文章，也可以拆成几篇；
反过来不行——篇的划分服从节的划分。

| # | 节 | 状态 | 落地形态 |
|---|---|---|---|
| 1 | 诞生背景 | ⏸️ 已标记未展开 | — |
| 2 | 不用它，代价是什么 | ⏸️ 已标记未展开 | `code/src/02_cost/`（6 个场景中已完成 3 个） |
| 3 | 分类与层次 | ⏸️ 已标记未展开 | — |
| 4 | 代码对比 | ⏸️ 已标记未展开 | — |
| 5 | 业务场景 | ⏸️ 已标记未展开 | — |
| 6 | 上层结构 | ⏸️ 已标记未展开 | — |
| 7 | 语言演进 | ⏸️ 已标记未展开 | — |
| 8 | 与相邻概念的边界 | ⏸️ 已标记未展开 | — |
| 9 | 真实项目案例 | ⏸️ 已标记未展开 | — |
| 10 | 待展开清单 | ⏸️ 已标记未展开 | — |

状态口径：`✅` = 正文写了、代码进了 `code/`、验证跑过（三条齐了才算）；
`⏸️` = 知道要写什么但还没写；`⬜` = 知道缺东西但还不知道缺什么。

进度表按**节**记而不按篇记：按篇排的表在第一次返工重排章节时就会作废，
按节排的不会——节的划分服从知识依赖，不服从排版。

**为什么没有「是什么」这一节。** 正文开头会有一两句话说明它是什么，但那几句话**不占节号**：
名词定义没有终止条件，说不清答到哪算完，扩成一节只会得到一个写不完的百科条目。
节 1 问的是来历、节 2 问的是代价——两者都有终点。理由与依据见根 [`TEMPLATE.md`](../TEMPLATE.md) §2。

## 运行

```bash
cd code
sh run.sh                          # 构建并运行全部
sh run.sh 02_cost                  # 只构建并运行第 2 节
sh run.sh 02_cost 01_select        # 只运行某场景的 old / new 对照
sh clean.sh                        # 清掉全部构建产物
```

Debug 产物在 `build-debug/`，与 `build/` 分目录，避免反复切换触发全量重编。
新增节或场景 = 只建目录、只放 `old.cpp` / `new.cpp`，**不改动任何 CMake**。
