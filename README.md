# design-pattern

C++ 设计模式实践库。**一个模式一个自包含文件夹**——演化背景、知识拆解、可编译代码、问题复盘都在同一处，互不依赖。

## 目录约定

```
design-pattern/
└── <pattern-name>/    一个模式的实现
    ├── README.md      该模式的导航（从哪读起、已知问题在哪）
    ├── docs/          正文，一篇文章一个文件（markdown + 内嵌 Mermaid + 手写 SVG）
    │   └── assets/    手写 SVG 具象图
    ├── code/          配套示例，每个场景一个自包含子目录
    └── notes/         问题记录与复盘（可选：真踩过坑才建）
```

**知识进仓库，过程出仓库。** 进度、决策记录、系列排期、原始素材都留在仓库外——公开仓库只承载结论，不承载到达结论的路径。

## 快速开始

**没有工程根统一构建**——按场景跑，每个场景自带入口：

```bash
bash factory-pattern/code/01_birth/build.sh      # 第 1 节：三痛点 + 可测试性对照（含 gcov）
bash factory-pattern/code/A06_plugin/build.sh    # A06：dlopen 插件，五组实验
cd factory-pattern/code/03_simple_factory/multi_tu && bash run.sh   # 03：多 TU 重建范围实测
```

单文件示例不必走脚本，正文里直接给了命令（`g++ -std=c++17 -Wall xxx.cpp -o /tmp/x && /tmp/x`）。

**依赖**：读文档只需一个支持 C++17 的编译器（GCC 9+ / Clang 10+）与 `python3`；
跑场景示例个别需要 `-fsanitize=address`，取覆盖 / 符号数据另需 `gcov` / `nm`（分别随 `gcc` / `binutils`）。
**无任何非系统默认依赖**——图全部是矢量（Mermaid 内嵌 + 手写 SVG），不需要栅格化。

## 体例约定

- **代码块标出处 —— 只对「引用他人的代码」要求。** 「来源」专指**公开论坛 / 仓库中引用的他人代码**
  （2026-09-30 定案）：引用时标出出处，出自配套工程写 `// code/<场景>/<文件>（节选）`，
  引用标准库写 `// 标准库签名（摘自 <头文件>），非本仓库代码`，引用论坛 / 仓库写库名 + 文件 + 函数名。
  **本文档自己写的教学示例没有来源，不要求标注**（工厂模式实测 76 个代码块：76 个原创、0 个引用）。
  读者据此判断哪一段能直接拿去编译。
- **涉及 C++ 标准版本差异的论断，必须落成一个能被编译器检查的装置**，不能只写在正文里。
- **图**：统一用 Mermaid 内嵌，不引用外部渲染服务；需要具象画面（内存布局 / 指针关系 / 对象状态）
  时用手写 SVG，放进该模式的 `docs/assets/`。**不做动图**（2026-09-30 取消：它会把
  `rsvg-convert` + `Pillow` 两项非系统依赖拖进来，而它表达的「一段时间里的状态变化」
  Mermaid 时序图或多帧静态 SVG 已能覆盖）。
- **开源案例必须回源核验**：能指出真实文件与函数名，不接受转述。
