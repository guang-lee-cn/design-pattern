# 观察者模式（Observer Pattern）

C++ 学习与实战子项目。**主线 9 篇 + 收口 1 篇**，编排见 [`docs/00-讲解计划.md`](docs/00-讲解计划.md)。

## 目录约定

```
observer-pattern/
├── docs/              正文：主线 9 篇（01~09）+ 收口 1 篇（10）
│   └── assets/        手写 SVG 具象图（矢量，直接内嵌）
├── code/              自包含场景目录（已建 `02_cost/`、`04_compare/`）
└── notes/             问题记录与复盘（001 起）
```

`docs/` 三层命名：主线 `NN-`（子编号写 `04a-`）、专题 `A0N-`、检验 `quizNN-`。

## 图例体例

- **结构类**（流程 / 决策树 / 时序 / 节点依赖）→ Mermaid 内嵌正文；
- **具象类**（内存布局 / 指针关系 / 对象状态）→ 手写 SVG 存 `docs/assets/`，
  正文用 `![](assets/xxx.svg)` 引用。**不要把 SVG 源码直接贴进正文**——GitHub 会过滤内联 `<svg>`。
- **本项目不做动图。** 这是相对参照实例的一处体例改动：GIF 必须逐帧栅格化才能合成，
  会为一张图拖进 `rsvg-convert` + `Pillow` 两项非系统默认依赖；而它表达的「一段时间里的状态变化」，
  Mermaid 时序图或多帧静态 SVG 已能覆盖。**图全部是矢量，不需要任何栅格化。**
- 硬约束：**主线每篇 ≥ 1 图**；**全库平均 ≥ 1 图 / 200 行**。

## 状态

- **进行中**：正文 **4 / 10 篇**（`01-诞生背景` / `02-不用它的代价` / `03-谱系` / `04-代码对比`）；`code/`、`docs/assets/`、`notes/` 均已建
- 学习大纲已过拍板（2026-09-30）：**谱系取宽口径** —— 回调列表 → 观察者 → 发布订阅 → 事件总线/响应式流，四层
- 第 3 节回源结论：**前三层共线**（解耦项数 0 / 1 / 3，斜率由「名单放在哪」决定），**第四层的两个名字不在同一根轴上** —— 事件总线是退回进程内换路由，响应式流是加第 4 维（速率）
- 第 4 节实测结论：**四层用代码把刻度占满 0 / 1 / 2 / 3**（事件总线的「2 项」由代码坐实，不再只是推论）。三条度量：① 发布方返回 3 次而接收方跑 0 次（`pending=3 dispatched=0`）；② 只有「自己持有名单」的那一层数得出人数；③ 加第二种事件时，只有观察者层被编译器拦下（点名 2 个既有接收方）
- 专题篇与检验篇**暂不预设**：等第 9 节案例回源后按「该模式在真实仓库里哪里有」再选
- 协作方式：小步快走，一问一答；一轮推进一个节，完成即停
