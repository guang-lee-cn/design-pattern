# 001 · 回源工序的四个坑

> 记于第 3 节（谱系）回源期间。四个坑都能复现，且都会**静默给出错数字**，不报错。
> 工序背景：把 PDF 一手件下载到本地，用 `pdftotext` 提文本，再用词频穷举证明「某术语在源头存在/不存在」。

## 坑 1 · `file` 报的 PDF 页数不可信

```bash
file manyfaces.pdf      # → PDF document, version 1.2, 10 page(s)     ← 错
pdfinfo manyfaces.pdf   # → Pages: 18                                 ← 对
```

同一份 `manyfaces.pdf`（CSUR 35(2) 2003，pp. 114–131，**18 页**），`file` 只看到 10 页 —— 它读的是 PDF 元数据，不是真实页树。

**后果**：用 `file` 判「下载是否完整」，会把一份完整的 18 页论文判成「缺了 8 页」，然后去重下或换源。

**判据**：**验完整性一律用 `pdfinfo`。** `file` 只用来确认「这是个 PDF、没下成 HTML 错误页」。

## 坑 2 · `bash -c "... grep -o -i 'publish[-/ ]*subscribe' ..."` 转义被吃

```bash
wsl -e bash -c "grep -o -i 'event[- ]*bus' manyfaces.txt | wc -l"
# grep: Unmatched [, [^, [:, [., or [=
# 0            ← 报错被 | wc -l 吃掉，只剩一个「0」，看起来像「不存在」
```

双引号里 `\$`、`\[` 一层层被剥，最后 `grep` 收到的是半个字符类。**`0` 是假的**，是 `grep` 报错后 `wc -l` 数了个空输入。

**后果**：这正是回源工序里最危险的一类错误 —— 「某术语在源头出现 0 次」是本工序要证明的核心结论，而这里报出的 `0` 只是转义失败的残骸。**有对照的 0 才可信**（见 skill 里的四步法第 3 步），转义失败制造的 0 连对照都做不了。

**判据**：**凡是带字符类（`[`）的词频统计，一律进 Python 的 `re.findall`，不走 shell 的 `grep`。** 落盘前的复核也走同一条路：

```bash
wsl -e python3 -c "
import re
t = open('manyfaces.txt', encoding='utf-8', errors='replace').read()
for pat in [r'publish[/\- ]{0,2}\s*subscribe', 'observ', 'decoupl', 'notif']:
    print(f'{pat:32s}', len(re.findall(pat, t, re.I)))
"
```

## 坑 3 · `pdftotext -layout` 双栏输出左右栏交错

`-layout` 保住了版面（表格、图注还对得上），代价是**双栏 PDF 的两栏被交错编进同一行**：

```text
... The strength             information on a software bus (an event
of this event-based interaction style                  manager) and consumers subscribe ...
```

左栏的句子和右栏的句子在同一行里交替出现。直接读会读成一句不通的话，`grep -A/-B` 取上下文取到的也是错位的行。

**判据**：**读上下文用 `grep -n` 拿行号、再 `sed -n 'A,Bp'` 看整段，不要用 `-A/-B` 连续行。** 拼合引文时要按左右栏分别顺读，拼完回头核一遍语义通不通 —— 这一步没有工具能代做。

> 别为此改用 `pdftotext`（不带 `-layout`）：那会丢表格结构，而 Eugster03 表 1 正是本节的核心证据。

## 坑 4 · 词频正则不跨行，折行会漏计

```bash
# 不跨行
grep -o -i 'publish[/- ]*subscribe' | wc -l     # 71
# 跨行版（\s 含换行）
python3 -c "... r'publish[/\- ]{0,2}\s*subscribe' ..."   # 72
```

差 1 次 —— 就是排版把 `publish/` 和 `subscribe` 拆到两行的那一处。

**后果**：绝对数会偏低。本例偏差小（1/72），但**不能假设它总是小**：词越长、连字符越多，折行概率越高（`publish-subscribe` 比 `observer` 容易折得多）。

**判据**：**报词频时同时报「不跨行」与「跨行」两个数，或统一用跨行版。** 更稳的做法是把它当**比值**用而不是当绝对数用 —— 本节要证明的是立场（72 : 4 ≈ 18 : 1），比值对 1 次的偏差不敏感，绝对数敏感。

## 四个坑的共同点

四个都不报错，都静默给出一个**看起来合理的错数字**。回源工序的产出全是「某某词在源头出现 N 次」这类量化结论，所以这一路上**唯一可信的复核方式是换一条独立路径重算一遍**（换工具 / 换正则 / 换读取方式），而不是看输出像不像对的。
